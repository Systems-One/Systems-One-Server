# s1_dash Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `Systems-One-Dash`, a logged-in customer and operations dashboard that replaces every Grafana panel and adds data-driven insights, and the Ansible role that runs it on `s1_server` port 8094.

**Architecture:** One FastAPI process serves a static single-page front end (vanilla JS, vendored ECharts) and a scoped JSON API over pyodbc to `S1_Remote_Monitoring`; a 15-minute in-process job maintains two derived tables (`dbo.dash_expected_profile`, `dbo.dash_storage_forecast`). Tenancy is a SQL predicate from the session cookie, applied in every device query. The image is built by GitHub Actions, pushed to a private GHCR package, and pulled by a thin role in Systems-One-Server.

**Tech Stack:** Python 3.12, FastAPI 0.115, uvicorn, pyodbc 5.2, bcrypt, itsdangerous, pytest, ECharts 5.5.1 (vendored), Docker, GitHub Actions, Ansible.

**Spec:** `docs/superpowers/specs/2026-10-30-s1-dash-design.md` (Systems-One-Server). Task 1 copies it to `docs/` in the new repo.

## Global Constraints

- Two repositories. Application: `C:\Dev\Systems-One\Systems-One-Dash` (GitHub `Systems-One/Systems-One-Dash`, private, default branch `main`). Deploy role: `C:\Dev\Systems-One\Systems-One-Server` on branch `feat/s1-dash-role`. Tasks 1 to 24 are in the application repo; Tasks 25 and 26 in Systems-One-Server.
- No JavaScript build toolchain, no front-end framework. ECharts 5.5.1 vendored from `Systems-One-Server/roles/s1_monitor/files/app/static/vendor/echarts.min.js`.
- Every timestamp in the database is UTC; every SAST boundary is computed with `TZ_OFFSET_HOURS` bound as a SQL parameter inside a subquery (`DATEADD(HOUR, ?, ts_datetime) AS local_ts`). No `GETDATE()` anywhere under `app/queries/`.
- Every SQL string under `app/queries/` that reads a device table joins `dbo.devices d` and contains the literal `{scope}` placeholder, filled by `scope.predicate()`.
- Rates are `100 * SUM(part) / SUM(total_items)` over rows in the bucket, never averages of row percentages. Percentage axes fixed 0 to 100.
- Low-volume thresholds: per 5-minute bucket `MIN_ITEMS_PACKET=5`, per 30 minutes `MIN_ITEMS_HALF_HOUR=15`, per hour `MIN_ITEMS_HOUR=30`, per day `MIN_ITEMS_DAY=100`.
- Liveness: `OFFLINE_GAP_MINUTES=11`, `STALE_DAYS=14`; state names `online`, `offline`, `stale`, `never`.
- Bucket chooser: span up to 48 h gives 300 s; up to 14 d gives 1800 s; up to 60 d gives 3600 s; otherwise 86400 s.
- Session cookie name `s1dash`, HttpOnly, SameSite=Lax, `Secure` when `SESSION_SECURE=true`; lifetime `SESSION_DAYS=30` when "keep me signed in", otherwise a browser-session cookie.
- Error bodies never carry exception messages: `{"detail": "<ExceptionClassName>"}`.
- Customer strings are exact `dbo.devices.customer` values: `BEX`, `DCB`, `MADIBANA`, `PEP`, `PEP AFRICA`, `PEPKOR`, `SNOWSOFT`.
- Commit messages: conventional (`feat:`, `test:`, `chore:`), ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Tests run with `python -m pytest tests -q` from the repo root; `tests/conftest.py` puts `app/` on `sys.path`.

## Review Focus

1. A viewer requesting `/api/explorer?devices=1,2013` where 2013 belongs to another customer must get the in-scope device only, not a 404 for the whole request and not the foreign series. Pinned in Task 14.
2. A device whose `dbo.devices.created_at` is inside the 30-day availability window must have its expected row count measured from `created_at`, not from the window start, or new devices show as 10% available. Pinned in Task 15.
3. A custom range where `to` precedes `from`, or spans more than 400 days, must return 400, not an empty 200 or a runaway query. Pinned in Task 3 and Task 14.
4. A `drives_json` value that is NULL, empty, or not a JSON array (older snapshots) must not break the storage forecast for the whole device. Pinned in Task 7 and Task 9.
5. A login attempt behind cloudflared with no `CF-Connecting-IP` header (direct Tailscale preview) must throttle on `request.client.host`, and ten failures from one address must not lock out a different address. Pinned in Task 4.
